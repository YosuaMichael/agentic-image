# 2026-09-24 — Qwen-Image-2.1 as the default model (full + Unsloth Q8)

## Objective

Add **Qwen-Image-2.1** ([QwenLM/Qwen-Image-2.1](https://github.com/QwenLM/Qwen-Image-2.1),
weights [`Qwen/Qwen-Image-2.1`](https://huggingface.co/Qwen/Qwen-Image-2.1)) as the
**default** image model, replacing Ideogram 4 (kept as a legacy engine). Cover both
the **full original weights** (bf16 safetensors via `diffusers.QwenImage21Pipeline`)
and the **Unsloth Q8 quant** ([`unsloth/Qwen-Image-2.1-GGUF`](https://huggingface.co/unsloth/Qwen-Image-2.1-GGUF),
file `qwen-image-2.1-Q8_0.gguf`), and compare them side by side on this machine
(RTX 4090 24 GB, Windows native CUDA).

## Decisions (amend D1/D4, additive — nothing is silently contradicted)

- **Q1 — Two engines, Qwen default.** `[models].default = "qwen21"`,
  `available = ["qwen21", "ideogram4"]`. Ideogram 4 stays fully working
  (scripts, skills, weights cache untouched); new sessions default to Qwen.
  This supersedes D1's "single model" for all new work.
- **Q2 — Plain-text prompts for Qwen.** Qwen-Image-2.1 reads a plain `prompt.txt`
  (plus optional `image` inputs for editing); there is no structured-caption
  discipline. For `qwen21` sessions the model-read artifact is `prompt.txt`;
  `caption.json` is not required and `verify_caption.py` does not gate Qwen
  takes. This scopes D4 (JSON-only) to `ideogram4` sessions.
- **Q3 — Diffusers backend, separate venv.** Both Qwen variants run through
  `diffusers` `QwenImage21Pipeline` (Day-0 support,
  [PR #14804](https://github.com/huggingface/diffusers/pull/14804)) in a NEW venv
  `~/.venvs/agentic-image-qwen21` (torch cu128 + `transformers>=5.17` + diffusers
  from git + accelerate + pillow). The Ideogram venv is never touched.
- **Q4 — Two quant variants, one pipeline.** `quantization = "full" | "q8_0"`:
  - `full`: `Qwen/Qwen-Image-2.1` safetensors, `torch_dtype=bf16` (~47 GB repo,
    7.1B transformer + Qwen3-VL-8B text encoder + RGBA VAE).
  - `q8_0`: Unsloth `qwen-image-2.1-Q8_0.gguf` transformer (denoiser-only GGUF)
    loaded via diffusers single-file GGUF path with text encoder + VAE from the
    full repo; if diffusers GGUF load proves unsupported for this class,
    fallback is `stable-diffusion.cpp` `sd-cli` with the Unsloth-recommended
    companions (VAE `qwen_image_2.1_vae_bf16.safetensors`, text encoder
    `Qwen3-VL-8B-Instruct-UD-Q4_K_XL.gguf`) — recorded here if taken.
- **Q5 — Ungated weights, same NC hygiene.** Qwen weights are UNGATED (no HF_TOKEN,
  no gate click) but under the **Qwen Research License (non-commercial)** — same
  handling as Ideogram NC: `commercial_use = false`, never describe output as
  commercially usable, notice file carries the attribution.
- **Q6 — Defaults for iteration speed.** `steps = 40` (upstream default),
  `width/height = 1024/1024` for drafts (native is 2048²; 1024² keeps iteration
  fast — the exact analog of the Ideogram "iterate small / finish big" rule),
  `guidance_scale = 1.0` per SGLang cookbook default, seeds cycle
  `[generation].seeds`.

## Architecture (additive)

```
compose-brief (qwen21) → studio/sessions/<id>/{brief.md, prompt.txt}
generate-qwen21        → scripts/generate_qwen21_take.py (generate_qwen21/v1)
                         → scripts/render_qwen21.py in qwen venv
                           (render_qwen21_inner/v1, diffusers, one load per call)
                         → takes/take-NN.png + .metadata.json (generate_qwen21_meta/v1)
setup                  → scripts/setup_qwen21.py (setup_qwen21/v1):
                         venv + full prefetch + Q8_0 GGUF prefetch
weights                → models/hf-hub/models--Qwen--Qwen-Image-2.1 (full)
                         models/gguf/qwen-image-2.1-Q8_0.gguf (+ companions if sd.cpp)
```

Scripts stay stdlib-only at the dispatch layer; only `render_qwen21.py` runs
inside the venv (torch + diffusers), mirroring the `render_batch.py` split.

## Comparison protocol (acceptance for this plan)

Same prompt (neon "QWEN IMAGE 2.1" sign, rainy night — upstream's own example),
seed 42, 1024×1024, 40 steps, back to back on the same GPU:

1. `full`: wall time (load + diffusion split), peak VRAM (`nvidia-smi` poll),
   PNG bytes + dims, typography note.
2. `q8_0`: same measurements, same seed.
3. Verdict: default `quantization` for `[qwen21]` + measured table in
   `model-guide` and here. Visual winner presented via the artifact gallery.

## Results (2026-09-24, RTX 4090 24 GB, session `20260924-000000-qwen21-compare`)

| | take-01 `full` (diffusers bf16) | take-02 `q8_0` (sd-cli GGUF) |
|---|---|---|
| Backend | `QwenImage21Pipeline`, torch 2.11 cu128, CPU offload | sd-cli master-908, Q8 denoiser + Q4_K_XL encoder + bf16 VAE, all in VRAM |
| Load | **10.1 s** | ~1–3 s (GGUF tensor load; part of 44 s total) |
| Diffusion (40 steps euler) | **38.4 s** (~0.96 s/step) | **43.35 s** total `generate_image` (~1.08 s/step) |
| End to end | ~48 s | **44.0 s** |
| VRAM | offloaded (not polled; fits via CPU offload) | **12.3 GB** resident (4.4 enc + 7.3 denoiser + 0.6 VAE) |
| PNG | 1,823,154 B, 1024² exact | 2,818,245 B, 1024² exact |
| Typography | "QWEN IMAGE 2.1" perfect, multicolor neon | "QWEN IMAGE 2.1" perfect, red/blue neon |
| Composition | wide multicolor sign, glass facade | red-glow facade, street-level framing |

Both renders are strong; neither shows a quality defect at 1024². The Q8
keeps full typography fidelity — no quantization damage visible on this
text-heavy prompt.

## Verdict

- **Default stays `full`** (best-practice quality, diffusers-native path,
  single-backend story). Q8 is a first-class alternative when download size
  (7.6 GB vs 47 GB) or all-in-VRAM footprint (12.3 GB) matters.
- **diffusers GGUF single-file load does NOT work for this class**
  (`img_in.weight` shape mismatch — plan risk Q4 fallback TAKEN): the Q8
  path is `stable-diffusion.cpp` `sd-cli` (prebuilt win-cuda12 under
  `.tools/sd.cpp/`, gitignored) with Unsloth companions (VAE bf16 +
  `Qwen3-VL-8B-Instruct-UD-Q4_K_XL`). Wiring Q8 into `generate_qwen21_take.py`
  as a second backend is open work (tracked below).
- **Speed class: ~45 s per 1024²/40-step take** (either variant) — ~2.4×
  faster than Ideogram TURBO single-take (~115 s) on the same GPU.

## Follow-ups (not this plan)

- Q8 backend inside `generate_qwen21_take.py` (`--quantization q8_0` currently
  expects the diffusers path and fails; route to sd-cli instead).
- Per-diffusion VRAM peak for `full` (poll `nvidia-smi` mid-render).
- 2048-native timing + RGBA/editing smoke takes.

## Risks

1. **diffusers main drift** (Day-0 class name `QwenImage21Pipeline` may move).
   Mitigation: `setup_qwen21.py` probes the import and reports the installed
   commit; pin to a working commit on failure.
2. **GGUF transformer load path uncertain.** Mitigation: try diffusers
   `from_single_file` GGUF first; fall back to sd.cpp (plan records which).
3. **47 GB full weights + ~7.5 GB Q8** on disk. Mitigation: C: has 288 GB free;
   weights live gitignored under `models/` (never committed).
4. **40 steps @1024² wall time unknown** (likely 1–3 min + encoder load).
   Mitigation: measure first, then set draft/final guidance like the Ideogram
   TURBO/QUALITY split if a faster step count proves visually sufficient.
